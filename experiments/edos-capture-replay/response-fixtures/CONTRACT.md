# Offline EdOS response fixtures: a new consumer contract

2026-10-27, declared before this retrospective qualification/calibration. The consumer is a developer or CI test of the frozen EdOS candidate/reference response contract. It needs three recorded JSON answers for deterministic regression checks; it does not emulate an authenticated server or execute saves. This distinct contract does not replace the original full capture/replay contract or its FAIL results.

Choose this bounded step over another browser experiment because v0.12 already retained the selected responses, while its unresolved general coverage and native browser cause remain explicit. A report with a renamed success metric would be insufficient: deliver a pinned fixture pack and an executable consumer that refuses known unsafe matches.

No new browser, target/replay server, product change, install or build. Read original captures v0.10/v0.11/v0.12, matching manifests/MCP replies and independent synthetic fixture/file state. Freeze their raw hashes and externally retained Evidence IDs before calibration. Reuse REA's parseEvidence/loadEnvironmentSource/replayedBody to authenticate semantic identities, parent relationships and ordinal/exchange derivation. Bind the selected POST request bytes independently to the predeclared fixture; never infer POST intent from exact_match:true. All selected response bodies must be whole, untruncated, exact-match, bound to the correct capture/record and deeply equal the independent filesystem/fixture oracle.

Output decision: QUALIFIED_RESPONSE_SUBSET or REJECTED, with scope offline-regression-fixtures and full_capture_acceptance:FAIL retained. Produce an immutable JSON pack only for a qualified input. An external SHA-256 pin is mandatory at consumption; an embedded self-hash is insufficient. The consumer accepts only an explicit offline purpose, exact method/path/literal query and structurally exact non-secret request body. It rejects extra headers/auth claims, unknown query, changed POST and ambiguous records. It returns historical, untrusted-content provenance and a fresh clone, never fresh authorization or write execution.

Expected known-corpus calibration: v0.10 rejects its missing candidates response; v0.11 rejects its missing reference response; v0.12 can qualify the three-response subset while its full gate remains FAIL. These are known retrospective cases, not a hidden holdout. Freeze and execute negative perturbations for mismatched manifest/capture, wrong external ID/hash, semantic tamper, missing/truncated response, forged oracle body, unknown query, changed POST and attempted live/authenticated purpose. Altered artifacts must be rejected even if their inner metadata claims success. Record every case and relevant refusal reason, not only aggregate counts.

Do not splice captures, synthesize missing response bytes, infer absent GET bodies from not_exposed, relax or replace original assessment, or modify historical receipts. Publish only the reviewed synthetic selected bodies/pack and authored tooling; keep raw captures, private source, credentials and host paths local. This is reusable test data and guard behavior, not independent external reproduction, complete request visibility, full UI/stateful emulation, release/adoption or measured productivity. End this step after meaningful positive and refusal checks, evidence and existing draft PR updates.
