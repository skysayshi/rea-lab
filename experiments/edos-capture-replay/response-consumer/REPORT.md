## Decision and limits

The reusable harness provides a real consumer regression check for source reading
and refusal behavior. It advances v0.13 beyond a standalone fixture-selection
example, while preserving its original narrow scope. No product correction is
warranted by these observations. The tested minimal dirty save requires a different
recorded request before a full save-flow replay can be qualified; do not weaken
strict matching to obtain compatibility.

The strongest next candidate, if save-flow qualification is needed, is a separately
declared synthetic capture using the actual editor request contract. Keep that
separate from browser-cause diagnosis and from this read-path result. No new capture,
install, build, product-source edit or release was performed in this checkpoint. Historical
full-capture FAIL, original wire-body limitations and unknown browser cause remain.
Actual DOM/UI, storage, write tracking, successful save, current-release behavior,
owner adoption and product effect are unobserved. PWP already covers these
produced/checked/used/effect distinctions; no global protocol update was needed.
